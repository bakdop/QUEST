# Long-form questions and rubrics (evidence_first)

This is the variant of the open-ended pipeline that produced the long-form SFT
question set (2,005 questions, each with a 20-25 item rubric). It differs from the
upstream flow in [README.md](README.md) in two places:

- **Question generation** uses `PROMPT_VARIANT=evidence_first`: one ReAct loop per
  question that searches wide around a sampled trending keyword, records every
  retrieved fact as a *statement* (verbatim quote + url), and writes the question
  last. A second pass removes figures that leaked from the statements into the
  question.
- **Rubrics** are generated by `longform_rubric/generate_criteria_evidence.py`,
  grounded in the run's own retrieved corpus rather than in the question alone.
  No reference answers are produced.

```text
generate_longform_tasks.py   ->  extract_evidence.py  ->  fix_leaks.py        ->  generate_criteria_evidence.py
(ReAct loop, 122B on vLLM)       (trajectories ->         (rewrite leaked         (one rubric per question,
                                  proposed_qa.jsonl)       figures, 122B)          grounded in the corpus)
outputs/<run>/trajectories/      outputs/<run>/proposed_qa.jsonl                   outputs/<run>/criteria.jsonl
```

## Setup

Two virtualenvs at the repo root, both used by the launchers:

| venv | contents | used for |
|---|---|---|
| `.venv` | Python 3.10, `pip install -r requirements-longform.txt` (pinned; the upstream `requirements.txt` also pulls torch + an older vllm, which this pipeline does not use) | generation, extraction, rubrics |
| `.venv-vllm` | `pip install vllm==0.26.0` | serving the model |

Model: `Qwen3.5-122B-A10B` (bf16, ~234 GB), served by vLLM as `qwen3.5-122b`.
Every LLM call (proposer, page summariser, leak rewrite, rubric writer) goes to
this one local server; no cloud LLM key is needed.

Keys (question generation only; rubrics need no internet):

```bash
export SERPER_API_KEY=...   # search tool (google.serper.dev)
export JINA_API_KEY=...     # visit tool (r.jina.ai)
```

The launchers export everything else the code reads (`SERPER_KEY_ID`,
`JINA_API_KEYS`, `DEEPRESEARCH_*`, `SUMMARY_MODEL_NAME`, `API_BASE`, tool cache
paths), so no `env.local.sh` is required.

## 1. Generate questions

Slurm (one TP=2 server per array task, 262k context), from the repo root:

```bash
mkdir -p logs
export MODEL_PATH=/path/to/Qwen3.5-122B-A10B
NUM_ITERATIONS=512 WORKERS=32 sbatch task/open_ended_task/run_evidence.sbatch
# -> outputs/ev512_<jobid>_0/ and outputs/ev512_<jobid>_1/
```

Single 8-GPU node, no Slurm (two TP=4 servers, 64k context):

```bash
MODEL=/path/to/Qwen3.5-122B-A10B N=512 WORKERS=16 bash task/open_ended_task/run_evidence_node.sh
# -> outputs/ev<MMDD_HHMM>_a/ and outputs/ev<MMDD_HHMM>_b/
# PROXY=http://host:port if outbound traffic needs a proxy
```

Each launcher serves the model, runs `generate_longform_tasks.py`, then
`extract_evidence.py` and `fix_leaks.py` while the server is still up.
Trajectories are flushed per question, so a killed run keeps its finished work:
re-run the two post-processing scripts over `trajectories/` to recover it.

Seeding: each question samples a topic from `category_structure` and one keyword
from `task/trending_keywords/merge_keywords/<domain>.csv`.

## 2. Generate rubrics

```bash
# Slurm: one run directory per array task
export MODEL_PATH=/path/to/Qwen3.5-122B-A10B
RUN_DIRS="outputs/ev512_123_0 outputs/ev512_123_1" sbatch --array=0-1 task/open_ended_task/run_criteria.sbatch

# single node: directories dealt across two servers
MODEL=/path/to/Qwen3.5-122B-A10B RUN_DIRS="outputs/ev1004_0930_a outputs/ev1004_0930_b" \
  bash task/open_ended_task/run_criteria_node.sh
```

Smoke test first with `LIMIT=16`, which writes `criteria_sample16.jsonl`.
`criteria.jsonl` is opened with `"w"`: a re-run starts that directory over.

Knobs (env): `CRITERIA_MAX_WORKERS` (16), `CRITERIA_MAX_TOKENS` (16000),
`CRITERIA_CORPUS_CHARS` (160000), `CRITERIA_REASONING_EFFORT` (none).

## Output schema

`proposed_qa.jsonl` (one row per question): `prompt` (the question), `topic`,
`keyword`, `subtopics`, `statements`, `findings` (statements in the older findings
schema), `centre`, `research_path`, `trajectory` (trajectory filename, the join
key used downstream), `_axes`, `_signals`.

`criteria.jsonl`: the same row plus

```json
"rubrics": [{"criterion": "...", "weight": 1-5, "axis": "Comprehensiveness | Insight | Implicit Criteria | Instruction Following | Readability",
             "grounding": ["S1: '...'"], "why_it_matters": "..."}],
"_rubric_corpus_chunks": 37
```

Weights are positive only (1-5).

## Downstream

The SFT data pipeline (rollouts, rubric judging, revision, dataset build) lives in
OpenDR-eval, branch `feat/longform-sft-data-lookahead`:
`scripts/data_preprocess/quest_to_source.py` converts `proposed_qa.jsonl` +
`criteria.jsonl` into its question format, and the rubric judge joins rubrics back
by `trajectory`. The 2,005-question set built with this pipeline is published on
ModelScope as `boyan9/quest-ev2k-questions`.
